# 对照实验：GroundedRAG vs 裸 prompt RAG

这份对照回答评审最关心的实证问题：**校验门相比"检索增强后直接让 LLM 回答"，
到底可复现地拦掉了多少幻觉？**

## 方法论（控制变量）

两条流水线喂**同一批召回文档与同一组问题**，只差在是否经过 GroundedRAG 的约束与校验：

| 维度 | 裸 prompt RAG（对照组） | GroundedRAG（实验组） |
|------|------|------|
| 召回 | 同一 BM25 top-k | 同一 BM25 top-k + 规则匹配 |
| 提示词 | "根据资料直接回答"（无约束） | 要求逐条主张 + `[证据n]`/`[规则n]` 锚点 |
| 校验 | 无 | 声明级校验门（引用完整性/表面一致/冲突裁定/充分性） |
| 输出门 | 模型说什么就是什么 | PASS 原样 / ANNOTATE 标注 / REFUSE 拒答或删除 |
| 指标口径 | 整段"会/不会拒答" | 主张级三指标（见 [metrics.md](metrics.md)） |

**评测不走真实 LLM**：实验组的候选主张由 `examples/eval_set.jsonl` 显式注入
（既含正确输出也含幻觉变体），被测对象是确定性校验链路；对照组用
`groundedrag.eval.runner.baseline_questions()` 导出同源问题清单后，在任意
裸模型上逐题问"会/不会拒答"，再用 `score_baseline()` 打分。这样实验组离线可复现，
对照组只需一个裸模型，两侧共享同一批"幻觉高危题"。

## 实测数值

> 🎙️ **真实 LLM 实录见 [control_experiment_live.md](control_experiment_live.md)**（2026-09-07，
> xiaomi / mimo-v2.5-pro）。本文的数值分两层，勿混淆：
>
> - **离线确定性层（本表）**：校验链路把"模型可能吐出的幻觉高危主张"（12 条，显式注入）
>   逐条拦下 —— 无 LLM、可复现，是**机制的拦截有效性**。
> - **在线真实 LLM 层（附录）**：同一批检索资料，裸模型同题同料重复采样行为**不可复现**
>   （缓解率一题 8 次采样 3 次补出资料外数值），其文本引用为自述、不可审计；
>   GroundedRAG 确定性交付、缺据不编、无锚不放行。
> - 因此下表裸列只是"离线口径下的基线设定"，**不主张**任何裸模型"一定从不拒答"。

内置评测集构造了 19 组 24 条主张，期望分布为 **10 通过 + 12 拒答 + 2 标注**；
其中 12 条拒答项即"裸 RAG 极易直出"的幻觉高危题（数值虚构、证据侧否定翻转、
禁忌联用、类型自报绕过等）。`python -m groundedrag.eval.runner --json` 实测实验组：

| 指标 | 裸 prompt RAG（离线设定） | GroundedRAG |
|------|------|------|
| 拒答正确率 `refusal_expected_caught` | 随模型不可复现（真实行为见[实录](control_experiment_live.md)：缺据数值 8 采样 3 次直出） | **1.0**（12/12 幻觉高危题全部拦截） |
| 误拒 `false_refusal` | 裸侧无校验门，无所谓误拒 | 0（10/10 好主张零误伤） |
| 标注正确率 `annotate_rate` | —（无标注概念） | 1.0（2/2 非关键降级项标注正确） |
| 引用完整性率 | —（无锚点概念） | 1.0 |
| 表面一致率 | —（无主张粒度） | 1.0 |

> ⚠️ 数值随评测集演化而变化，README/本文件的表格需与 `python -m groundedrag.eval.runner --json`
> 的实际输出同步更新；勿在评审材料里用过期的声称数值。

一句话叙事：**裸 RAG 在"这份资料里没有的事"上依赖模型自觉——同题同料重复采样
不可复现，缺据数值（如缓解率）会从参数记忆直出（实录 8 采样 3 次）；GroundedRAG 对
同一批资料把输出拆成一条条可核查主张，逐条过确定性校验门：无锚点不放行、缺据数值
不编造、规则冲突不静默二选一——整段拒答用就医指引文案兜底。**

## 如何复现

```bash
# 1) 实验组：确定性校验链路（无需 LLM）
python -m groundedrag.eval.runner --json

# 2) 对照组：导出问题清单 → 在你的裸模型上逐题问"会/不会拒答"
python - <<'PY'
import json
from groundedrag.eval.runner import load_eval_set, baseline_questions
for q in baseline_questions(load_eval_set("examples/eval_set.jsonl")):
    print(q["index"], json.dumps({"question": q["question"]}, ensure_ascii=False))
PY

# 3) 把裸模型"会/不会拒答"的 bool 按 question 键写回 responses → score_baseline
```

跑真实演示对照（同一问题两条流水线并排输出），打开 Gradio 界面的**裸 RAG 对照开关**：

```bash
pip install -e ".[demo]"
python examples/app.py     # 切换「GroundedRAG 可信模式 / 裸 RAG 对照」
```

## 边界与诚实声明

- 表面一致率 ≠ "真实支持率"，关系型主张以拒答正确率为准（见 [metrics.md](metrics.md)）。
- 本对照证明的是**校验机制的拦截有效性**，不是某个模型在医学问题上的总准确率；
  语义档（NLI/更强模型二次核验）关闭时，方向性主张一律拒答或标注，不冒充验证过。
- `examples/` 数据为自研合成示例，不构成真实诊疗建议，不用于训练或医学结论。

## 典型案例

> ⚠️ 以下为**示意**：为便于理解，每条把"某种典型失效形态 + 校验门如何拦"并排展示，
> 演示的是机制而非对某一模型的实测。真实单模型行为随模型/提示浮动且不可复现——
> 以 [control_experiment_live.md](control_experiment_live.md) 的实录为准。

### 案例 1：数值幻觉拦截

**问题**：「奥希替尼推荐剂量是多少？」

| 流水线 | 输出 | 结果 |
|--------|------|------|
| **裸 RAG** | "推荐剂量为 120mg 每日一次"（直出，无引用） | ❌ **数值虚构**（真实为 80mg） |
| **GroundedRAG** | 主张「推荐剂量为 120mg」→ 校验门：`number_mismatch`（证据写 80mg）→ **REFUSE** | ✅ **拒答**，提示"证据不足，建议就医" |

### 案例 2：证据侧否定翻转

**问题**：「一线可以使用吉非替尼吗？」  
**检索到的证据**：「吉非替尼**不推荐**作为一线标准治疗」

| 流水线 | 输出 | 结果 |
|--------|------|------|
| **裸 RAG** | "可以使用吉非替尼作为一线治疗"（实体命中，忽略否定词） | ❌ **方向翻转** |
| **GroundedRAG** | 主张「可以使用吉非替尼」→ 校验门：`evidence_negates_claim`（证据写"不推荐"）→ **REFUSE** | ✅ **拒答**，避免误导 |

### 案例 3：规则直出（有据可答）

**问题**：「EGFR 突变的晚期肺癌一线推荐什么方案？」  
**命中规则**：肺癌 + 一线 + EGFR 突变 → 奥希替尼（A 级证据，CSCO-2026）

| 流水线 | 输出 | 结果 |
|--------|------|------|
| **裸 RAG** | "推荐奥希替尼"（可能对，但无引用，无法审计） | 🟡 内容对，但不可溯源 |
| **GroundedRAG** | 规则直出："肺癌 一线 EGFR 推荐方案：奥希替尼 `[规则1]`" → 校验门：`rule_authoritative` → **PASS** | ✅ **权威背书 + 可溯源** |

## 为什么不是"又一个 RAG 框架"

与 LangChain / LlamaIndex / RAGFlow 的差异化定位：

| 维度 | 成熟 RAG 框架 | GroundedRAG |
|------|--------------|-------------|
| **解决的问题** | 怎么检索、怎么编排、怎么接入向量库/模型 | **怎么让 LLM 少输出没有证据的断言** |
| **核心能力** | 检索拼接 + prompt 工程 + 向量库抽象 | 约束生成 + 声明级校验 + 确定性拒答 |
| **输出门** | 拼接上下文后让 LLM 自由生成 | 逐条主张过校验门，无证据即拒答/标注 |
| **适用场景** | 通用问答、客服、内容生成 | 高风险垂直领域（医疗/金融/法律） |
| **可审计性** | 难（整段输出，事后难定位哪句来自哪条证据） | 强（主张级引用锚点 + EvidenceId 溯源） |

**一句话**：它们解决"怎么检索、怎么编排"；GroundedRAG 解决"怎么让 LLM 在检索增强后
仍然不编造 —— 以声明级校验门约束生成链路，无证据即拒答或标注，而非仅仅拼接上下文
后让 LLM 自由发挥。"

## 参考文献与相关工作

- **约束生成**：GroundedRAG 的声明级校验门受 Retrieval-Augmented Generation (Lewis et al., 2020) 
  与 Constrained Decoding 文献启发，工程化为确定性决策表 + 规则引擎。
- **可信 AI**：校验门设计借鉴 Explainable AI 中的"可溯源性"要求（每个输出可回溯到输入证据）。
- **医疗 NLP**：参考 ClinicalBERT / BioBERT 等垂直领域模型的审慎输出策略（宁可拒答，不可误导）。

GroundedRAG 的创新在于将上述理念整合为**轻量、可复用、领域无关**的开源框架，
并以 MIT 许可证开放给任何高风险垂直领域使用。
