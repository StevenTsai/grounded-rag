# 评测指标口径

GroundedRAG 用一组**确定性链路评测**回答一个关键问题：校验门到底拦住了多少
无证据输出，又不误伤多少好主张。评测**不走真实 LLM** —— 主张由内置评测集
`examples/eval_set.jsonl` 显式给出（一组"问题 + 若干候选主张 + 期望结论"，
候选主张里既含**正确输出**，也含精心构造的**幻觉/反例变体**），被测对象是
"检索 → 规则匹配 → 校验门"整条确定性链路。因此评测可离线、可复现、无 API 成本。

## 三个头条指标

评测集里每条主张都标注了期望结论 `expected ∈ {pass, refuse, annotate}`，
评测把"校验门实际给的状态"与期望逐条比对，聚合为三条指标：

| 指标 | 分子 / 分母 | 衡量的能力 |
|------|------|------|
| **引用完整性率**<br>`citation_completeness_rate` | 期望 `pass` 的主张中，`citation` 检查通过（引用锚点完整可解析）的数量 ÷ 期望 `pass` 的主张总数 | 有据主张确实**带上了完整、可解析的引用**（证据/规则锚点） |
| **表面一致率**<br>`surface_consistency_rate` | 期望 `pass` 的主张中，最终状态为 `pass` 的数量 ÷ 期望 `pass` 的主张总数 | 证据充分、要素一致的好主张**没有被误拒**（低误伤） |
| **拒答正确率**<br>`refusal_correctness_rate` | 期望 `refuse` 的主张中，校验门确实给出 `refuse` 的数量 ÷ 期望 `refuse` 的主张总数 | 无证据/自相矛盾/关系型主张**被成功拦截** —— **防幻觉的关键指标** |

另有三个辅助口径供细看：`annotate_rate`（非关键主张是否按预期降级为标注）、
`claim_accuracy`（主张级总正确率）、`answer_refusal_accuracy`（整组级"是否整段拒答"
与 `expect_refusal` 的一致性 —— 注意"部分主张被拒但保留有据部分"不算整段拒答）。

## 为什么"表面一致率"不叫"真实支持率"

确定性档只做**表面要素一致性**：主张里的实体 / 数值 / 单位是否**字面出现在**证据原文
（或所引规则内容）。它验证的是"**主张内容确实锚定在可溯源证据上**"，而**不声称**
"主张在语义上是真实/正确的"：

- 一个出现在证据原文、但语义上并不支持主张方向的数值，表面一致性**通过**；
  方向性问题（否定/比较/因果）由**关系型主张拒答**与**证据侧否定翻转拦截**负责，
  最终落到"拒答正确率"来度量，而不是塞进"一致率"冒充真实性。
- 因此三个头条指标各管一段：引用完整性管**锚点**，表面一致率管**误伤**，
  拒答正确率管**幻觉拦截**。三者合起来才构成对校验门效果的完整描述。

如果某套评测把这三项打包称为"真实支持率/准确率"，那是在夸大确定性校验的能力边界。
GroundedRAG 对外的措辞始终是：**确定性档保证"有据"，语义正确性留给更高门槛的
语义档 / 权威规则背书**。

## 复现

```bash
python -m groundedrag.eval.runner                  # 三条指标 + 逐组明细
python -m groundedrag.eval.runner --json           # 只输出 JSON 摘要
```

构造自己的评测集：参照 `examples/eval_set.jsonl`，每组形如

```json
{
  "question": "EGFR 突变的晚期肺癌一线推荐什么方案？",
  "context": {"cancer_type": "肺癌", "treatment_line": "一线", "biomarker": "EGFR"},
  "evidence_docs": ["doc-lung-egfr-1st-pos"],
  "claims": [
    {"text": "推荐方案：奥希替尼", "evidence_refs": ["doc-lung-egfr-1st-pos"], "expected": "pass"},
    {"text": "推荐方案：吉非替尼", "rule_refs": ["r-lung-egfr-1st"], "expected": "refuse"}
  ],
  "expect_refusal": false
}
```

反例变体（防幻觉压测）务必覆盖这几类，它们对应校验门的核心拦截逻辑：

- **无引用数值断言**（citation 门）：裸报"缓解率约 95%"无任何锚点 → 拒答。
- **数值不符**（surface 门 / number_mismatch）：主张 120mg vs 证据 80mg → 拒答。
- **证据侧否定翻转**：证据写"RAS 突变不应使用西妥昔单抗"，主张却"推荐西妥昔单抗" → 拒答。
- **关系型主张**：含真方向语义的否定/比较/因果（如"不可用 A"、"A 优于 B"、"A 导致…"）→ 确定性档无法验证方向 → 拒答。
  注意：线次定位词（一线/二线/后线）**不算**方向比较信号 —— 「一线用 A」这类定位主张站不站得住，
  由「药物 + 线次词须同现于同一证据」的表面核验把关（详见 architecture.md D1）。
- **类型自报绕过**：主张文本含禁忌词但被 LLM 标为 `factual`，校验门用表层信号覆盖为 negation → 拒答。
- **规则冲突 / 分歧**：同条件域两条同级同时间但互斥的规则 → 无胜出者，不静默二选一 → 拒答。
- **挂靠规则包装幻觉**：主张只复用规则条件域、偷换推荐药物 → 与规则内容高门槛表面比对 → 拒答。

## 裸 prompt RAG 对照组的计分差异

对照组没有校验门，不存在"主张级"三指标；它只回答"这份回答是否整段拒绝"。
用 `baseline_questions()` 导出问题清单（每项带 `expect_refusal`），让裸模型逐题作答
"会/不会拒答"，再用 `score_baseline()` 打两组分数：

- `refusal_expected_caught`：期望拒答（幻觉高危题）中被拦截的比例 —— 对照组通常 **≈0**，
  因为它"有资料就直出"，从不会拒答；
- `false_refusal`：不该拒答却被拒的比例 —— 对照实验方法论与预期数值见
  [comparison.md](comparison.md)。

## 指标演进计划

当前指标体系（v1.0）基于**确定性档**（表面要素一致性 + 关系型拒答）；随着 Roadmap 推进，
指标口径将同步升级：

| 版本 | 核心指标变化 | 说明 |
|------|-------------|------|
| **v1.0（当前）** | 引用完整性 / 表面一致率 / 拒答正确率 | 确定性档，关系型主张一律拒答 |
| **v1.1（语义档）** | + 语义支持率 / 分类拒答率（按主张类型细分） | 关系型主张从"拒答"升级为"语义校验" |
| **v1.2（图谱）** | + 证据链路完整性（多跳溯源覆盖率） | 实体-关系级证据链路 |
| **v1.3（对齐）** | + 多模型一致性 / 分歧标注率 | 并行生成 + consensus voting |

每个版本的指标定义与实现细节见对应分支的 `eval/runner.py` 与本文档更新版。

## 常见问题

**Q1: 为什么评测不走真实 LLM？**  
A: 被测对象是"检索 → 规则匹配 → 校验门"确定性链路（与模型无关），主张由 eval_set.jsonl 
显式注入（含正例 + 幻觉变体）；这样评测可离线、可复现、无 API 成本，且压测覆盖更全面。

**Q2: 表面一致率 1.0 是否意味着"输出 100% 正确"？**  
A: **不是**。表面一致率只衡量"好主张没被误拒"（低误伤），不衡量语义正确性；
关系型主张的正确性由"拒答正确率"体现（确定性档拒答，避免冒充验证过）。

**Q3: 如何提升拒答正确率？**  
A: ① 丰富 eval_set.jsonl 的反例覆盖（数值虚构/否定翻转/类型绕过）；② 调整校验门
决策表（`verifier.py` 的表面要素阈值/规则冲突裁定逻辑）；③ v1.1 启用语义档。

**Q4: 三指标全 1.0 是否代表框架已完美？**  
A: **不是**。三指标 1.0 只代表在**当前评测集（19 组 24 条）**上确定性链路无漏网，
不代表所有可能问题都覆盖；实际部署需根据业务场景持续扩充 eval_set + 监控线上拒答/误拒率。
