# Demo 视频脚本（3–5 分钟）

## 录制准备

- 录屏工具：OBS / macOS QuickTime
- 终端：放大字号（约 24pt），深色主题
- 麦克风：提前测音，消除环境噪音
- 建议先完整跑一遍 `python examples/demo.py` 熟悉节奏，再录

## 要录的终端命令（按顺序）

```bash
# 1. 主流程 demo（含规则直出 + 拒答 + 幻觉拦截 + 冲突裁定）
python examples/demo.py

# 2. 确定性校验门跑分（三项指标全 1.0，零 LLM）
python -m groundedrag.eval --json
```

> 注：`demo.py` 内部已含 LLM（若配置了 .env）或规则直出（无 Key），
> 无需网络也能完整跑通，评审现场/录屏都不会翻车。

## 口播脚本

### [0:00–0:20] 开场

> 大家好，我是 GroundedRAG 的作者。今天用三分钟，演示一个让大模型「有据可依、无据可拒」的框架。

（画面：标题卡「GroundedRAG — RAG 的确定性校验层」，一句话定位）

### [0:20–0:50] 痛点（30 秒）

> 大模型做 RAG，最大的问题不是它不够聪明，而是它**会编造**。同样一句话，同一个模型，
> 重复采样 8 次就有 3 次，会在声明「资料没提供」之后，又从记忆里补出资料外的数字。
>
> 更隐蔽的是「跨证据拼装」——把 A 指南的药名，和 B 指南的剂量，拼成一条看起来合理、
> 实际不存在的推荐。

（画面：可放一张「编造剂量 120mg」的反例截图，或直接进入演示）

### [0:50–2:10] 演示一：规则直出（有据可依）

（切到终端，运行 `python examples/demo.py`，滚动到第一个问题）

> 先看一个「有据可依」的例子。问题是「EGFR 突变的晚期肺癌一线推荐什么方案」。
>
> 系统先检索证据、命中权威规则「肺癌一线 EGFR → 奥希替尼，A 级」，
> 然后把答案拆成原子主张，逐条过校验门——**引用完整、表面一致、证据充分**，判定 PASS，原样输出。
>
> 注意这里 `used_llm=规则直出`——命中规则时，**一次 LLM 都不调用**，答案来自权威规则本身，零幻觉风险。

（画面停顿 2 秒，让评委看清 PASS 面板）

### [2:10–2:40] 演示二：拒答（无据可拒）

（滚动到「骨质疏松应该补什么钙」）

> 再看一个「无据可拒」的例子。这个问题不在知识库里，没有检索到证据、也没命中规则。
>
> 系统不猜、不编，直接结构化拒答——「现有证据不足，请以主治医生当面评估为准」。
>
> 这就是「宁可诚实拒答，也不流畅编造」。

### [2:40–3:40] 演示三：幻觉拦截（核心亮点，1 分钟）

（滚动到校验门分诊部分，逐条展示三组反例）

> 最关键的部分——幻觉拦截。这是三道陷阱题：
>
> **第一题**，问奥希替尼剂量，模型主张 120mg，但证据写的是 80mg。校验门做**数字比对**，
> 「数值与证据不符」，直接 REFUSE。
>
> **第二题**，问 RAS 突变能不能用西妥昔单抗。证据写的是「**不应**使用」，模型却作正向推荐。
> 校验门识别出「证据侧否定翻转」，拦截。
>
> **第三题**，EGFR 三线有两个互斥方案，等级相同、时间相同。校验门不偷偷选一个，
> 而是**声明分歧**——「请结合临床判断」。

（每个反例停顿 2–3 秒，让评委看清 REFUSE 原因）

### [3:40–4:20] 演示四：确定性跑分（收尾数据）

（切到第二个命令 `python -m groundedrag.eval --json`）

> 最后是确定性校验门的跑分。注意——这里**没有调用任何 LLM**，纯逻辑判定。
>
> 三项核心指标：引用完整率、表面一致率、拒答正确率，全部是 1.0。
> 12 条幻觉高危主张全部拦截，10 条好主张零误伤。
>
> 因为校验逻辑是字符串匹配、数字比对、规则裁定——**同一输入，永远同一输出**，可审计、可复现。

### [4:20–4:50] 收尾

> GroundedRAG 不是「又一个让模型更聪明的方案」，而是给 RAG 输出加一道**确定性校验门**。
>
> 专治「模型输出不可复现」。在医疗、金融、法律这些「出错成本极高」的领域，
> 一个诚实拒答的 AI，比一个流畅编造的 AI，更有价值。
>
> 谢谢大家。
